1.1. Abstract
This document specifies the core data structures and algorithms underlying the
X Paradox X rules engine, providing the concrete representations and time/space complexity
analysis required by 005_game_coding_standards.txt Section 1.8 for every module listed in
006_game_scaffolding.txt.

1.2. Key Words
data structure, algorithm, complexity analysis, board representation, seeded RNG, movement
legality, combat resolution.

1.3. Executive Summary
X Paradox X represents its board as a two-dimensional coordinate-indexed grid, pieces and
cards as immutable value objects mutated only through engine commands, and territories as a
map keyed by coordinate. Core algorithms (movement legality, combat resolution, territory
majority evaluation) operate in time complexity proportional to board size or piece count,
never worse than low-order polynomial for the board sizes supported by 017_game_rules.txt
Section 1.6.1.

1.4. Key Findings
1.4.1. The board is represented as a coordinate-indexed grid (dictionary or 2D array keyed by
(row, column)), not a flat list, to keep movement-legality lookups O(1) per tile.
1.4.2. All randomness (dice rolls, card shuffling/draws) flows through a single seeded RNG
service so that 009_game_unit_tests.txt Section 1.6.9's determinism requirement is satisfiable
from one shared implementation rather than ad hoc calls to the language's default random
module scattered across engines.
1.4.3. Movement legality evaluation for any single piece is bounded by the piece's own
maximum reachable-tile count, which is O(N) for sliding pieces (Rook/Bishop/Queen) on an
N x N board and O(1) for King/Knight/Pawn.
1.4.4. Combat resolution is O(1): two die rolls and a fixed comparison, per 017_game_rules.txt
Section 1.7.3.
1.4.5. Territory majority evaluation is O(T) where T is the total capturable-territory count
for the current board size, per 017_game_rules.txt Section 1.6.2.

1.5. Philosophical Preamble
Complexity analysis is not academic decoration here; it is the concrete evidence that the
performance budgets in 012_game_perfomance_tests.txt Section 1.7 are achievable by
construction rather than by luck, and it is required documentation content under
005_game_coding_standards.txt Section 1.8.

1.6. Core Data Structures

1.6.1. Board Representation
A dictionary keyed by `(row: int, column: int)` mapping to a Tile value object (tile type:
home/capturable/impassable/ordinary, per 017_game_rules.txt Section 1.6.2, and optional
occupying piece reference). Space complexity: O(N^2) for an N x N board.

1.6.2. Piece Representation
An immutable value object per piece instance: piece type, owning player, current position,
current HP, and the fixed Attack/Defence stat-block for its type (017_game_rules.txt Section
1.7.2). Mutation (movement, HP change) occurs only by replacing the object through an engine
command, never by direct field assignment, consistent with the rules-engine-sole-authority
principle (003_game_philosophy.txt Section 1.6.1).

1.6.3. Deck and Hand Representation
The 52-card deck (017_game_rules.txt Section 1.10.1) is represented as an ordered list of
immutable Card value objects (suit, rank); a player's hand is a separate list of Card objects
removed from the deck on draw. Space complexity: O(1) relative to board size (fixed at 52
cards regardless of board size).

1.6.4. Territory Representation
A dictionary keyed by `(row, column)` mapping to a Territory value object: owning player (or
neutral), consecutive-turns-held counter, and optional upgrade type (017_game_rules.txt
Section 1.9.3). May be a view over the same coordinate space as the board (Section 1.6.1)
rather than a fully separate structure, at implementation discretion, provided the one-way
import direction in 006_game_scaffolding.txt Section 1.6 is preserved.

1.6.5. Event Log Representation
An append-only ordered list of structured log entries (per 020_game_logging_standards.txt),
each entry immutable once appended, supporting the statistics derivation described in
010_game_player_statistics.txt Section 1.4.1.

1.7. Core Algorithms

1.7.1. Movement Legality Evaluation
For a given piece, enumerate candidate destination tiles per its real-chess movement pattern
(017_game_rules.txt Section 1.7.1), stopping a sliding piece's ray at the first occupied or
impassable tile encountered. Time complexity: O(N) per direction for sliding pieces
(Rook/Bishop/Queen), O(1) for King/Knight/Pawn, on an N x N board.

1.7.2. Combat Resolution
Draw one seeded die roll (Section 1.7.4) for the attacker and one for the defender, apply the
fixed comparison table in 017_game_rules.txt Section 1.7.3. Time complexity: O(1).

1.7.3. Territory Majority Evaluation
Iterate all capturable territories once, tallying ownership per player, compare each player's
tally against more-than-half of the total capturable count (017_game_rules.txt Section
1.11.1). Time complexity: O(T), where T is the capturable-territory count for the current
board size.

1.7.4. Seeded Random-Number Service
A single service wrapping a seedable pseudo-random generator, exposing `roll_die()` and
`shuffle_deck()` operations; the seed is persisted as part of save data
(015_game_deployment.txt Section 1.7.1) so that replaying from a save reproduces subsequent
rolls and draws identically. Time complexity: O(1) per die roll; O(52) per full deck shuffle
(constant, since deck size is fixed).

1.8. Complexity Analysis
| Operation | Time Complexity | Space Complexity |
|-----------|-------------------|----------------------|
| Board initialization | O(N^2) | O(N^2) |
| Movement legality (sliding piece) | O(N) | O(1) additional |
| Movement legality (King/Knight/Pawn) | O(1) | O(1) additional |
| Combat resolution | O(1) | O(1) |
| Territory majority evaluation | O(T) | O(1) additional |
| Deck shuffle | O(52) = O(1) | O(52) = O(1) |
| Card draw | O(1) | O(1) |

1.9. Summary Table
| Structure/Algorithm | Representation/Approach |
|------------------------|-----------------------------|
| Board | Coordinate-keyed dictionary of Tile objects |
| Piece | Immutable value object, replaced on mutation |
| Deck/Hand | Ordered list of immutable Card objects |
| Territory | Coordinate-keyed dictionary of Territory objects |
| Event log | Append-only ordered list |
| Movement legality | Directional ray-casting per piece type |
| Combat resolution | O(1) seeded dice comparison |
| Territory majority | O(T) single-pass tally |
| Randomness | Single shared seeded RNG service |
